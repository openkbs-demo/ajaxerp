## 1. Цели

- **G6-1.** Seed-to-meat проследимост: за всяка продадена партида — пълна верига назад: генетика (родителско стадо) → хале → силоз (фураж/рецепта) → ветеринарен дневник (лекарства, ваксини) → дезинфекции → карентни срокове
- **G6-2.** Електронен Дневник №1 (БАБХ): автоматично генериране на регулаторен документ — ваксинации, дезинфекции, смъртност, третирания по период
- **G6-3.** ВЕТИС сертификат: документ за ветеринарен статус при експедиция (здравен статус на групата, карентни срокове, ваксинации)
- **G6-4.** ИАСРЖ регистър: регистър на животните (стадо) — категории, движения, бракувани, продадени за период
- **G6-5.** Dashboard разширение: секция "Проследимост" с брой генерирани документи, последни документи, статус

## 2. Функционални изисквания

### 2.1 Seed-to-Meat проследимост (FR-6100)

- **FR-6101.** `traceability.generate` за група (animal_groups.id): агрегира и връща пълна верига:
  - **Партида**: group_name, hall, entry_date, exit_date, entry_count, exit_count, entry_weight, exit_weight
  - **Генетика**: source_litter_ids → litters → birth_sow → ear_tag, breed, parity
  - **Хале**: hall_name, sector, biosecurity_zone
  - **Фураж**: silos в халето → recipe_id → recipe name, components, cost_per_ton. Feed production batches за периода
  - **Ветеринарен дневник**: events (vaccination, treatment, disease) за групата/халето за периода → medicine_name, дата, дозировка, карентен срок
  - **Карентни срокове**: active_withdrawals за групата — medicine, start, end, status
  - **Дезинфекции**: disinfection_logs за МПС, hall_hygiene_pauses за халето
  - **Транспорт**: dispatch_orders → vehicle, driver, weight_loading, weight_destination, shrinkage
- **FR-6102.** Резултатът се записва в `traceability_records` като JSONB за архив
- **FR-6103.** Генерация по заявка (не автоматична) — потребителят избира група
- **FR-6104.** Визуализация: chain view — стъпка по стъпка от генетика до кланица

### 2.2 Електронен Дневник №1 — БАБХ (FR-6200)

- **FR-6201.** Генериране за период (from_date, to_date): автоматично попълва:
  - **Ваксинации**: дата, хале, брой третирани, медикамент, доза, извършил (от events тип vaccination)
  - **Дезинфекции**: дата, хале/МПС, средство, извършил (от disinfection_logs + hall_hygiene_pauses)
  - **Смъртност**: дата, хале, категория, брой, причина (от events тип death)
  - **Третирания**: дата, хале, медикамент, доза, карентен срок, извършил (от events тип treatment)
  - **Движения**: трансфери между халета, дата, брой глави (от events тип transfer)
- **FR-6202.** Формат: структурирани секции с номериране, дати ДД.ММ.ГГГГ
- **FR-6203.** Статуси: `draft` → `final` → `submitted`. Final е неизменяем
- **FR-6204.** CSV експорт по секция (ваксинации, дезинфекции, смъртност, третирания)

### 2.3 ВЕТИС сертификат (FR-6300)

- **FR-6301.** Генериране при експедиция (dispatch_orders.id):
  - **Животни**: група, брой глави, средно тегло, хале на произход
  - **Здравен статус**: последни ваксинации, активни/изтекли третирания, карентни срокове (от active_withdrawals)
  - **Дезинфекции**: последна дезинфекция на халето и на МПС
  - **Сертификация**: "Групата е свободна от карентни срокове" или "ВНИМАНИЕ: активен карентен срок"
- **FR-6302.** Реф. номер: автоматично генериран (VET-YYYY-NNNN)
- **FR-6303.** Статуси: `draft` → `final` → `submitted`
- **FR-6304.** Свързване с dispatch_orders

### 2.4 ИАСРЖ регистър (FR-6400)

- **FR-6401.** Регистър стадо за период:
  - **Начално състояние**: брой по категория (gilt, sow, boar, weaner, finisher) към start_date
  - **Движения**: +родени, +закупени, −продадени, −умрели, −бракувани
  - **Крайно състояние**: брой по категория към end_date
  - **Баланс**: начално + входящи − изходящи = крайно (валидация)
- **FR-6402.** Разбивка по хале
- **FR-6403.** Реф. номер: REG-YYYY-NNNN
- **FR-6404.** CSV експорт

### 2.5 Dashboard и разширения (FR-6500)

- **FR-6501.** Dashboard секция "Проследимост": брой генерирани traceability записи, брой документи (по тип и статус), последни 5 документа
- **FR-6502.** `regulatory.list` с филтри (тип, статус, период)
- **FR-6503.** CSV експорт за всеки тип документ

## 10. Ограничения

- Без реална интеграция с БАБХ/ВЕТИС/ИАСРЖ системи — генерира документи за ръчно подаване
- Документите са в JSONB формат с CSV експорт — без PDF генериране

- ВЕТИС сертификатът е информативен — без електронен подпис
- Реф. номерата са вътрешни — не са синхронизирани с външните системи
