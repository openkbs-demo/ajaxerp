## 2. Функционални изисквания

### 2.1 Управление на МПС (FR-3100)

- **FR-3101.** Регистрация МПС: рег. номер (UNIQUE), тип (`feed_truck`/`livestock_transport`), капацитет (тона), назначен шофьор, начален километраж
- **FR-3102.** Статус машина: `clean` → `dirty` (след маршрут) → `clean` (след дезинфекция). Допълнителни: `maintenance`, `out_of_service`
- **FR-3103.** Списък МПС с филтри (тип, статус, активни)
- **FR-3104.** Статистика по МПС: завършени курсове, общо тонове, общо км за период

### 2.2 Силози (FR-3200)

- **FR-3201.** Силоз принадлежи на хале. Полета: име, капацитет (тона), текущо ниво, тип фураж, свързана рецепта, праг за ниско ниво (по подразбиране 20%)
- **FR-3202.** Уникален силоз: `UNIQUE(hall_id, silo_name)`
- **FR-3203.** Ръчно зареждане: увеличава `current_level_tons`, не може да надвиши `capacity_tons`
- **FR-3204.** Проверка нива: силози под прага → аларми (< 20% warning, < 10% critical)
- **FR-3205.** Процент запълване: `fill_pct = (current_level / capacity) × 100`

### 2.3 Маршрути за доставка (FR-3300)

- **FR-3301.** Създаване маршрут: избор МПС + шофьор + спирки `[{silo_id, tons}]` + км старт
- **FR-3302.** Биосигурностна валидация: МПС трябва да е `clean`. Ако е `dirty` → грешка с указание за дезинфекция
- **FR-3303.** Валидация капацитет: `SUM(tons) ≤ capacity_tons` на МПС
- **FR-3304.** Статуси: `planned` → `in_progress` → `completed` / `cancelled`
- **FR-3305.** Завършване: за всяка спирка — `delivered_tons`, актуализация на `silo.current_level_tons`. МПС → `dirty`. Записва `km_end`
- **FR-3306.** Отмяна: само за маршрути със статус `planned`

### 2.4 Заявки за експедиция (FR-3400)

- **FR-3401.** Ръчно създаване: група, дата, купувач, дестинация, МПС, шофьор, брой глави
- **FR-3402.** Автоматично предложение (`dispatch.autoCheck`): групи с `current_weight_avg_kg ≥ 122` и без активна заявка → `proposed` за дата +3 дни. Генерира info аларма
- **FR-3403.** Workflow: `proposed` → `confirmed` → `loading` (тегло при товарене) → `in_transit` → `delivered` (тегло при кланица) / `cancelled`
- **FR-3404.** Фира: `shrinkage_pct = (weight_loading - weight_destination) / weight_loading × 100`
- **FR-3405.** Авто-продажба при `delivered`: запис в `sales` (тип `finisher`, цена 2.95 лв/кг). Обновяване на `animal_groups.exit_date`

### 2.5 Дезинфекционен дневник (FR-3500)

- **FR-3501.** Запис: МПС, потвърждение за измиване, потвърждение за дезинфекция, извършил, бележки
- **FR-3502.** Ако и двете потвърдени → МПС `status = clean`, обновява `last_disinfection_at`
- **FR-3503.** Списък записи с филтри (МПС, дата)

### 2.6 Нова роля персонал (FR-3600)

- **FR-3601.** Роля `driver` (Шофьор) — добавена към валидни роли за регистрация
- **FR-3602.** Шаблон заплата: 3 250 лв/месец
- **FR-3603.** 7 шофьори в seed данните (Иван Петров, Георги Димитров, Стоян Стоянов, Димитър Иванов, Петър Георгиев, Николай Тодоров, Христо Николов)

### 2.7 Отчети логистика (FR-3700)

- **FR-3701.** Ефективност фуражовози: за период — завършени курсове, общо доставени тонове, средно тонове/курс, общо км, общо часове
- **FR-3702.** Фира при транспорт: списък доставени експедиции с тегло товарене, тегло кланица, фира %. Средна фира за период
- **FR-3703.** CSV експорт за маршрути (`delivery_routes`) и експедиции (`dispatches`)

### 2.8 Разширение на Dashboard (FR-3800)

- **FR-3801.** Нова секция "Логистика" в Dashboard: МПС по статус (чисти/мръсни), силози под минимум, активни маршрути днес, предстоящи експедиции
- **FR-3802.** Логистични аларми в `alerts.check`: силоз < 20% → warning, < 10% → critical

## 5. Нови DB таблици (6)

### `vehicles`
id, plate_number (UNIQUE), vehicle_type (feed_truck/livestock_transport), capacity_tons, status (clean/dirty/maintenance/out_of_service), assigned_driver_id → personnel, current_km, last_disinfection_at, notes, is_active, created_at

### `silos`
id, hall_id → halls, silo_name, capacity_tons, current_level_tons, feed_type, recipe_id → feed_recipes, low_level_threshold_pct (DEFAULT 20), last_filled_at, notes, is_active, created_at. UNIQUE(hall_id, silo_name)

### `delivery_routes`
id, route_date, vehicle_id → vehicles, driver_id → personnel, status (planned/in_progress/completed/cancelled), total_tons, started_at, completed_at, km_start, km_end, notes, created_by → personnel, created_at

### `delivery_stops`
id, route_id → delivery_routes (ON DELETE CASCADE), stop_order, silo_id → silos, planned_tons, delivered_tons, status (pending/delivered/skipped), delivered_at, notes. UNIQUE(route_id, stop_order)

### `dispatch_orders`
id, group_id → animal_groups, dispatch_date, buyer_name, destination, vehicle_id → vehicles, driver_id → personnel, head_count, weight_at_loading_kg, weight_at_destination_kg, shrinkage_pct, status (proposed/confirmed/loading/in_transit/delivered/cancelled), auto_generated, notes, created_by → personnel, created_at

### `disinfection_logs`
id, vehicle_id → vehicles, disinfection_date, wash_confirmed, disinfect_confirmed, performed_by → personnel, notes, created_at

## 10. Ограничения

- Без GPS/реално проследяване — километраж е ръчен запис
- Без RFID/QR интеграция — дезинфекцията се потвърждава ръчно
- Силозни нива — ръчно обновяване (без сензори)
- Без оптимизация на маршрути (TSP алгоритми) — ръчен избор на спирки
- `dispatch.autoCheck` не е автоматичен cronjob — извиква се ръчно
